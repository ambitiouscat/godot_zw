# 自动保存机制

## 概述

使用 `CronCreate` 工具实现会话期间的定时自动保存。

---

## 默认配置

- **启用状态**：默认启用
- **保存间隔**：60 分钟
- **Cron 表达式**：`7 * * * *`

---

## Cron 表达式说明

### 推荐表达式

```
7 * * * *
```

**设计原因**：
- 避开整点 (:00) 触发，减少与其他任务的冲突
- 每小时第 7 分钟执行一次

### 其他可选间隔

| 间隔 | Cron 表达式 | 说明 |
|------|-------------|------|
| 60 分钟 | `7 * * * *` | **默认推荐** |
| 30 分钟 | `7,37 * * * *` | 避开整点 |
| 15 分钟 | `7,22,37,52 * * * *` | 避开整点和半点 |
| 10 分钟 | `3,13,23,33,43,53 * * * *` | 高频保存 |
| 5 分钟 | `*/5 * * * *` | 高频保存（不推荐） |

---

## 创建定时任务

### 命令格式

```
CronCreate
  cron: "7 * * * *"
  prompt: "/workspace save --auto"
  recurring: true
```

**说明**：
- 技能注册名称为 `workspace`
- `--auto` 参数标识这是自动保存调用
- 返回 `job_id` 存储在会话文件中

---

## 触发条件

### 核心规则：仅在有新对话时才更新

**检测逻辑**：
1. 检查 `.workspace-session-skill/conversation.log` 的修改时间
2. 与会话文件中的 `last_update` 时间比较
3. 有新对话（修改时间晚于上次保存） → 执行保存
4. 无新对话（修改时间 ≤ 上次保存） → 执行二级验证，确认是否真的无新对话

**二级验证**（mtime 假阴性防护）：

`conversation.log` 的 mtime 可能因文件系统延迟、日志未及时刷盘等原因落后于实际对话时间，产生假阴性。当 mtime 判定"无新对话"时，必须通过以下信号交叉验证：

| 验证信号 | 检查方式 | 说明 |
|---------|---------|------|
| 上下文感知 | 当前 cron 周期内是否有代码编辑、文件操作、构建、git 操作等实质性工作 | 最直接的信号，优先级最高 |
| session.md 变更 | session.md 的 mtime 是否晚于 last_update | session.md 被更新说明有状态变更 |
| git 变更 | `git diff --stat HEAD` 或 `git status --short` | 未提交的代码变更说明有实际工作 |
| 显式标记 | 用户是否要求保存或提到需要持久化 | 用户意图不应被 mtime 技术问题阻挡 |

**任一信号命中即视为"有新对话"，执行完整保存。全部未命中才跳过。**

**目的**：
- 避免频繁写入文件系统
- 保持时间戳准确性（反映实际对话时间）
- 减少不必要的 I/O 操作
- **防止因 mtime 假阴性导致工作内容丢失**

---

## 触发行为

当定时任务触发且有新对话时：
1. 读取当前会话文件
2. 更新 `last_update` 时间戳
3. 静默保存，不中断用户

**注意**: 任务仅在 REPL 空闲时触发。

---

## 会话文件记录

```yaml
autosave: 60m
cron_job_id: "job_abc123"
```

---

## 用户控制

### 调整间隔

用户可在开始工作时指定间隔：

```
/workspace start --autosave 15m
```

### 禁用自动保存

```
/workspace start --no-autosave
```

### 手动停止自动保存

```
/workspace save --stop-autosave
```

调用 `CronDelete(id: cron_job_id)` 删除定时任务。

---

## 跨天自动停止

当定时任务检测到跨天并生成昨日总结后，会自动关闭定时任务（`CronDelete`）。原因：

- 跨天总结生成说明当天工作已结束（晚间时段）
- 后续无需继续定时运行，节省资源
- 次日 `/workspace continue` 时会自动重新创建


## 结束工作

"结束工作" (`/workspace end`) 时自动删除定时任务。

---

## 最佳实践

1. **使用默认 60 分钟间隔** - 平衡保存频率和性能
2. **关键决策后手动保存** - 确保重要信息不丢失
3. **结束时检查** - 确认最后状态已保存
4. **无需频繁手动保存** - 系统自动检测新对话

---

## 注意事项

- 定时任务仅在当前会话有效
- 最多运行 7 天后自动过期
- 系统重启后需要重新创建（`/workspace continue` 会自动重建）
- 无新对话时不会触发写入操作
- 日志文件超过 1MB 会自动轮转

---

## 日志轮转

对话日志文件 `.workspace-session-skill/conversation.log` 会自动轮转：
- **触发条件**：文件大小超过 1MB
- **处理方式**：重命名为 `conversation-{timestamp}.log`
- **新文件**：创建新的空日志文件继续记录

**注意**：日志轮转是**重命名**操作，不会删除任何已有内容。轮转后的日志文件永久保留。
